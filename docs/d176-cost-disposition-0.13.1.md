## Risk reviewed

A new broad exception handler in a test or `conftest.py` can honestly forward a failing assertion. A production change that the analyzer cannot interpret, such as a Cython edit, supplies insufficient evidence that the assertion can still fail. D-190 recognizes a bounded set of failure relays. An honest relay outside that set can therefore produce a high-severity `BROAD_EXCEPT_ADDED` finding that blocks the change. Its frequency in the rest of history remains unmeasured. The previous R4 census completed 881 comparisons and left 6,554 incomplete, including one partial member. [D-176 history and limits](https://github.com/taipei49314/checkwash/blob/0477013159face076a2c6a887f9d5b235c76d5e5/docs/d176-cost-disposition-0.13.0.md)

The two releases have exactly the same Git blobs for the gating implementation (`c1b9a6e31dc6ba5c7011ccc088f271341de67f7d`) and Python failure-relay recognizer (`89e4947faa6cfd6a7452b6edddbcc77dcf5ffca8`). The broad-handler finding has no test unit. D-176 excludes the opaque file-level evidence route before D-199 applies its more general refusal. The 0.13.1 product change adds bounded recognition of a test replacing an imported subject, a separate path. ## Grounds for the recommendation

The refusal protects against treating an opaque production edit as evidence that a test can still fail. The known cost on the three named relays remains removed. The separate R29 comparison found zero report or outcome changes on 3,600 fixed in-sample commits. Those sets contain no uvloop commit and provide no estimate of the frequency of other honest relays. A finding identifies the file and normalized first line of the handler. A maintainer can review a base-side exemption. Such an entry also covers other handlers with the same fingerprint in that file until its expiry or removal. The maximum lifetime is 180 days. The release-specific decision must acknowledge this trade-off.

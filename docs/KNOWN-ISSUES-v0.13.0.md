# Known issues for 0.13.0

Status, 2026-11-18: limits of the published v0.13.0
([publication record](releases/v0.13.0-publication-verification.md)). The
rows were written for the release candidate in the release pull request; the
Publication section was updated after publication.

From v0.13.0, each release gets one hosted verification on macOS and Linux
([RELEASING](RELEASING.md#hosted-release-verification),
[D-204](../DECISIONS.md)), two first-week behaviours change
([D-205](../DECISIONS.md)), a change to a commonly named test helper checks its
own top-level functions across `REPAIR_REFUSED_PYTHON` and emits an `analysis
incomplete` note instead of stopping every check under the default policy while
exiting 2 under `on_engine_error = "block"` ([D-206](../DECISIONS.md),
[D-212](../DECISIONS.md)), a Windows virtual environment's signed
`Activate.ps1` no longer blocks one ([D-207](../DECISIONS.md)), on Linux (macOS
by Python's source, not run locally) a virtual environment's own links no
longer stop a check without a range or the Stop hook ([D-208](../DECISIONS.md)),
findings on projected Python tests name the enclosing test rather than a
synthetic `test_concrete_*` identifier ([D-210](../DECISIONS.md)), changed
test-shaped files outside the Python and JS/TS test parse gates emit an
`analysis incomplete` note on stderr, the terminal report and SARIF
`toolExecutionNotifications` (#610, #616;
[embedding notes](embedding.md#v0120-to-v0130)), strict inert end-of-file
appends separated by a blank line in a tracked repository-root `CLAUDE.md` stay
at `warn` (`GUARDRAIL_ADDITIVE`, binding `"additive": True` into the v2
fingerprint context) while prepends, mid-file insertions, adjacent appends,
fences, comments, `---` delimiters, hidden/ignorable code points or edits to
existing lines escalate to `critical` ([D-211](../DECISIONS.md),
[D-213](../DECISIONS.md); [embedding notes](embedding.md#v0120-to-v0130)), and
CPython 3.12+ single-line `tokenize` memory growth, quiet `SyntaxWarning`
parsing and deep-expression runtime-shadow refusals are hardened (#613, #617,
#618). The [release guide](releases/v0.13.0-public-launch.md) describes each
change and what this release measured. Both Claude Code hooks are author-side
checks: the required CI check in range mode remains the gate.

This page carries the rows of the 0.13 section of
[KNOWN-ISSUES-next](KNOWN-ISSUES-next.md) into the release's own page; that
section stays there as the dated preparation record. The rows below are named
residuals, found by reading the code, its design and pre-release reviews, and
toy repositories unless a row names another source. Earlier limits remain in
[KNOWN-ISSUES-v0.12.0](KNOWN-ISSUES-v0.12.0.md),
[KNOWN-ISSUES-v0.11.0](KNOWN-ISSUES-v0.11.0.md) and the pages they link. A pass
means that no known tampering pattern was detected; it is not a correctness
guarantee.

## Measured for this release, and what was not

- **Fixed-corpus comparison.** On the 3,600 fixed in-sample commits, 0 move
  between pass, block and error against the published v0.12.0, and 0 `--format
  json` reports differ apart from the `run` block ([release
  guide](releases/v0.13.0-public-launch.md)). Python: 1,726 pass and 74 block;
  JS/TS: 1,748 pass, 50 block and 2 engine errors (apollo-client `8a51ea63` and
  undici `0f1f8903`, both symlink refusals with identical stderr). In-sample
  counts, not a false-positive rate.
- **uvloop relays.** The three uvloop regression-test additions that 0.10.0
  blocks still pass on 0.13.0 with no finding
  ([D-190](../DECISIONS-archive-4.md)).
- **D-176's remaining risk, not measured.** An honest broad `except` added
  around an assertion in a Python test or conftest, beside an opaque production
  change, still blocks at high unless D-190 proves it a failure relay, exactly
  as on 0.12.0 and 0.11.0; how often history holds one is not measured.
  Antigravity accepts that risk for 0.13.0 only, as a delegated decision after
  independent review ([0.13.0 disposition](d176-cost-disposition-0.13.0.md)).
- **Fingerprint movements outside R29 (`D-210`, `D-211`/`D-213`).** Projected
  Python unit findings whose v0.12.0 v2 key named `test_concrete_*`,
  `test_exception_*` or `test_local_auxiliary_*` move to the enclosing real
  Python test's qualified name ([D-210](../DECISIONS.md)), and strict inert
  end-of-file appends to repository-root `CLAUDE.md` move from v0.12.0's
  `critical` `GUARDRAIL_TOUCHED` v2 key (without `"additive"`) to an additive
  `warn` v2 key carrying `"additive": True` ([D-211](../DECISIONS.md),
  [D-213](../DECISIONS.md); non-EOF, adjacent, fenced, commented or editing
  changes to `CLAUDE.md` keep v0.12.0's byte-identical `critical` `META` key;
  see [embedding upgrade notes](embedding.md#v0120-to-v0130)).
- **Not measured by R29's `--format json` range mode:** stderr-only `analysis
  incomplete` notes for importer gaps (D-206, D-212) and changed test-shaped
  files (`B6`, #610, #616; [embedding notes](embedding.md#v0120-to-v0130))
  appear on `stderr`, `term` and SARIF `toolExecutionNotifications` rather than
  `--format json` stdout, and working-tree or hook-only changes (D-205, D-208)
  are not exercised on clean historical git ranges.

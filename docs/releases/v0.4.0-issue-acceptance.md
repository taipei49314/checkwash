## Integrated pre-tag checkpoint

The complete suite on immutable snapshot `84c1fb8` reports 3,503 passed,
one Windows symlink skip and three failures. Two are the same `035-identity`
frozen-record mismatch in independent consumers; one is the missing v0.4.0
tag. Public CI on that candidate has those same three failures on every leg,
plus an Ubuntu 3.12 performance failure (2.59 seconds versus the unchanged
2.5-second median budget). All nine raw corpus artifacts are byte-identical.
Later source changes require a fresh complete run and performance validation.

Review also reproduced production importing an apparently unused test helper:
the original suite failed twice and the edited suite passed twice. Removal of
helpers, unused fixtures and transparent forwarding definitions now requires
closed production-source proof. Factory consumers received the same
review. These checks protect against granting equivalence solely because a
definition has no references inside its own test module.

Further independent review exposed two false equivalence proofs and retained
their live failure-to-pass witnesses. A complete dictionary equality cannot
be exchanged for partial fields, including moving the complete check to a
different expected dictionary for the same input. A fixture's `request`
parameter cannot be treated as an imported callable with that name. The
repaired proof paths refuse both transformations; existing ordinary-parser
pass/warning residuals remain explicit and are not claimed newly blocked.

# v0.4.1 release guide

The maintainer authorized merging and publishing this repair on 2026-09-23.
[PR #166](https://github.com/taipei49314/checkwash/pull/166) integrates the fix
for [#164](https://github.com/taipei49314/checkwash/issues/164), including #165,
and the prevention work. The
[GitHub Release](https://github.com/taipei49314/checkwash/releases/tag/v0.4.1)
is the publication record and contains final-source validation and artifact
identities. This is a one-time release scope; subsequent releases need a new
maintainer instruction.

## What changes

Exact Node assertions such as `assert.strictEqual(total(), 5)` weakening to
`assert.ok(total())` are represented in IR and checked by the existing
detectors. Discovery includes Node default test paths such as `test/example.js`;
moving a test outside collection is treated as coverage removal. Static Node
ESM/CommonJS imports and Jest/Vitest `expect` aliases are resolved. Local
stand-ins, parameter/catch shadows and direct writes cannot retain an imported
assertion's strength. Preserving edits remain controls.

Unrepresented assertion candidates produce diagnostics in every CLI output
format. `--coverage-report FILE` writes a separate versioned JSON report;
existing findings and IR schemas, severity policy and exit codes are unchanged.
`no_known_gaps` describes a bounded scan, not complete JavaScript coverage.
Dynamic wrappers, computed access and template interpolation remain limits.
See [assertion coverage](../assertion-coverage.md) for the supported model.

The independent support inventory has 136 API/context cases and 248 concrete
mutations. Source, installed wheel and zipapp run the same Git-backed CLI
qualification. Receipts bind the source commit, package, artifact and suite
hashes. All three candidate jobs and `checkwash` are required on the default
branch, with strict up-to-date checks and no bypass actors.

## Evidence and limits

Final release qualification records the full test suite, self-check, fresh
fixed 1,800-commit sweep, source/wheel/zipapp contract results, nine-platform
tag CI and public asset checks. Each receipt identifies its source; earlier
candidate results do not establish the published package's identity. The
recorded historical sweep and its human adjudication remain unchanged; a new
sweep is not automatically a new false-positive adjudication.

The frozen legacy v0.3.3 byte comparison remains a disclosed cross-version
mismatch. Its comparator and failure are retained. The recommended Action
advances under the one-release trust lag to **v0.4.0**, commit
`6dd3158653c3569279fb2c56cef6af30a959d844`; that engine still lacks this release's
Node assertion repair. Its independent qualification reports actual misses
and remains distinct from the passing candidate checks. CLI and Action
versions must therefore be recorded separately.

Checkwash remains alpha. A pass does not prove correctness or honesty, and
publication does not establish natural-case acceptance for the limited quality
preview. No frozen fixture, severity lattice or performance gate is relaxed.

## Try it on a change you understand

With Python 3.11+ and Git, after publication:

```sh
pipx install checkwash==0.4.1
checkwash --version
checkwash demo
checkwash check HEAD~1..HEAD --format json --coverage-report coverage.json
```

Exit 0 means no blocking finding, exit 1 means a blocked change, and exit 2
means an analysis/input error. GitHub supplies the offline `checkwash.pyz`;
the wheel and sdist are also published to PyPI. The release record verifies
their GitHub/PyPI SHA256 hashes and the public CLI's version and demo.

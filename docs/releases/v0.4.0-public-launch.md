# v0.4.0 release guide

This is the source-bound release guide for the human-authorized estate T-436
release, integrated through [PR #160](https://github.com/taipei49314/checkwash/pull/160).
The [GitHub Release](https://github.com/taipei49314/checkwash/releases/tag/v0.4.0)
records publication status, final validation results and artifact identities.
The earlier [pause checkpoint](v0.4.0-pause-checkpoint.md) is historical;
the maintainer subsequently directed the local executor to finish publication.

## What changes

The issue-resolution scope is #84–93, #95, #130, #132, #140, #156, #158 and
#159. The candidate adds bounded detection for pytest execution/report hooks,
collection settings, fixture subject replacement and import-path providers;
expectation provenance, inherited test methods, checked doctest examples and
literal branch outcomes; and additional transparent table refactors.
JavaScript scanning separates real declarations from comments, strings and
regular expressions, retaining duplicate test-name multiplicity.

The maintainer adopted `SUBJECT_INPUT_CHANGED` in D-060. An unchanged oracle
can now report a concrete input rewrite to the same callable, including a
literal parameter table. The three previously silent frozen fixtures were
reclassified by that decision. Renames preserving values, row reorders,
pure additions, computed inputs and changed callable providers remain
controls. The [contract review](../issue-93-input-contract-review.md) explains
why this detects changed coverage rather than proving a concealed bug.

Two regressions found during independent review were repaired before the
release freeze. A table edit that changes the callable and its corresponding
data no longer invents a same-subject input finding. Boolean normalization
accepts the strengthening equality-to-identity direction; it does not erase
an identity-to-equality loss, even when current production returns Boolean
values. Historical cases 014 and 018 include integer wrong-type witnesses.
D-062's earlier count of 77 passing historical-folder cases includes these
two real losses and must not be read as 77 preserving refactors.

Metadata and CLI are 0.4.0. The recommended Action deliberately stays at the
prior stable v0.3.4, commit `23fce200561ae4a95e46539ed9e668088591d1c1`.
It does not include the new v0.4.0 detector and precision changes.

## Evidence and limits

Publication requires the final immutable source's full tests, self-check,
packages, fixed 1,800-commit sweep, byte-verified historical replays and public
tag checks. The release receipt records actual results rather than treating
an earlier candidate's measurements as final-source evidence. Nine OS/Python
matrix outputs must agree byte for byte, and install-from-tag must actually
install and execute the advertised tag.

The historical 178-case population contains 88 captured escapes and 90 cases
originally filed as false positives. Runtime controls classify the latter as
75 preserving changes and 15 real losses. The separate 381-case population
contains 300 saved escape samples and 81 historical false positives: 74
preserving changes and seven approximate-comparison losses. Those categories
remain separate. Runtime qualification of all 300 static escape samples has
not been performed; the 306 capped unsaved families are unavailable. Neither
missing samples nor optional unintegrated candidates are counted as fixed.

The fixed v0.3.3 raw quality comparison remains a disclosed cross-version
mismatch, as with v0.3.4. Its original comparator and exit status are retained.
The exact-source dossier accounts for typed findings/IR differences and the
human-approved #93 fixture changes. The existing schema-2 transition verifier
rejects any original fixture-byte change, so this dossier is **not** claimed
as `transition_qualification.qualified=true`. This is separate from the
required same-source nine-platform byte comparison. No comparison baseline,
performance threshold, severity gate or archived receipt is relaxed to
obtain a passing result.

Checkwash remains alpha. A pass is not proof of correctness or honesty;
unknown execution context and unmodeled carriers remain coverage limits.
The limited quality preview has not received natural-arm acceptance.
Earlier source-specific measurements remain in the
[pause record](v0.4.0-pause-checkpoint.md) and
[historical candidate record](https://github.com/taipei49314/checkwash/blob/5b8e3f7108a9120d868672b362c680c96b91e213/docs/releases/v0.4.0-public-launch.md).

## Try it on a change you understand

With Python 3.11+ and Git, after publication:

```sh
pipx install checkwash==0.4.0
checkwash --version
checkwash demo
checkwash check HEAD~1..HEAD --format json
```

Exit 0 means no blocking finding, exit 1 means a blocked change, and exit 2
means an analysis/input error. The offline zipapp is a GitHub Release asset;
the wheel and sdist are also published to PyPI. The release receipt verifies
the GitHub/PyPI wheel and sdist SHA256 hashes agree and checks the zipapp's
source members, version and demo. Record CLI and Action versions separately.

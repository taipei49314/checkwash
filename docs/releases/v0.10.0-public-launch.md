## Policy and input authority

BASE .greenwash predecessor. Creating a new path does not turn the reviewed
predecessor into defaults. IR3 records the required policy_shadows provenance.
Embedding callers must use the documented reviewed-BASE snapshot contract;
HEAD content does not authorize its own changes.

by --repo. The lexical BASE lookup and alias/nonregular-source refusals remain.
Recognized unsupported or ambiguous TASK policy is refused before a partial
scope or freeze subset can be applied. Historical fixture decoding stays a
separate compatibility path.

## Oracle preservation

Moving equal assertion text, retaining assertion mass, or keeping the same
test name does not prove the same oracle. D179 binds complete source context,
producer identity, inputs, setup and execution obligations independently on
BASE and HEAD. Unknown context earns no compensation. Proven complete units
can retain full-unit credit; assertion-only compensation still reaches freeze.

The new plain pytest class domain requires a complete bounded repository
inventory, closed producer/startup/call bindings, an unused receiver and a
symbolically inactive supported marker. The JS plain-describe domain requires
an exact single-file snapshot, explicit supported framework imports and a
closed literal-producer/assertion grammar. Other files, directives, callbacks,
bindings and unknown startup remain outside that domain. Both routes retain
the 128-statement bound and the existing liveness and credit-spending rules.
They do not execute the represented programs or prove universal equivalence.

Worktree/Stop analyses now receive paired pytest configuration evidence.
LF/CRLF-only relocations retain their declared textual identity while original
source bytes and physical inventories remain preserved. Stable-name JS/TS
expected bindings are compared by resolved definitions. Registered gitlinks
receive pointer treatment only with actual stage-0 mode160000 evidence.

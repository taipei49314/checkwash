# v0.6.0 release guide

The maintainer authorized this release on 2026-10-05 after the rulings of
2026-10-03 to 2026-10-05 on reports [#196](https://github.com/taipei49314/checkwash/issues/196)–[#261](https://github.com/taipei49314/checkwash/issues/261)
were worked through PRs #194–#265. The one-time scope is recorded in
[RELEASING](../RELEASING.md). The
[GitHub Release](https://github.com/taipei49314/checkwash/releases/tag/v0.6.0)
is the publication record. Preparation alone does not mean the version is
published.

## What changes

Each item reaches an existing detector unless it says otherwise. The
THREATMODEL row and the DECISIONS entry named in brackets hold the exact
boundary, pins and residuals.

- **A previous-release verdict gate** (#201, D-064, D-065). Every pull
  request runs the published release and the candidate through the CLI on the
  same cases, and a block that turns into a pass fails the gate unless the
  maintainer accepted it. A release waits for that gate on its final head, on
  `main` and on its tag.
- **JS/TS test paths keep their test obligations** (#197, row 107, D-067). A
  JS/TS test file whose path resolves to another role (a CI directory, a
  snapshot directory, a shebang or a `roles` glob) is still parsed and judged
  as a test, beside that role's own rules.
- **JS assertion meaning across APIs** (#198, rows 110 and 111, D-069, D-070).
  Jest matchers, chai `expect` chains, chai and Vitest `assert` calls and
  node:test asserts record the predicate they check and where their expected
  operand comes from. A rewrite between APIs that asserts something else is
  reported: an inverted or contradicting predicate, a widened one, a bound
  direction reversed, or an expected value or tolerance that changed.
- **Only collection controls withhold the collection inventory** (#199, row
  105, D-068). A conftest runtime control (a skip fixture, a setup or report
  hook) no longer withholds the resolved collection proof, so a first pytest
  config that narrows the suite blocks there too.
- **Runner evidence** (#196 186.x and 187.x, #217, rows 2 and 107, D-071 to
  D-074). The runner a JS/TS file's imports or the base `package.json` name
  decides whether a moved test is still collected, and which units a focus
  stops (Jest's rule unless the runner is proven to be Vitest, Mocha, Jasmine
  or node:test). Focus added to a file is reported for the whole suite unless
  the runner is proven to keep it in the file. Data, mocks and helpers beneath
  `__tests__/`, `__mocks__/` and Node's `test/` take the test role, so editing
  them buys no production exemption.
- **JS stand-ins and bounds** (#196 188.x and 189.1, #240, rows 109 and 110,
  D-075, D-076). `vi.mock` takes effect for the whole file, a stand-in is new
  for each test that did not have it, a spy replaced in a second statement is
  read, and every write to a bound reaches the binding scan. TypeScript
  annotations and casts on a bound declaration are read.
- **Hand-rolled tolerances in both frontends** (#196 189.2, #225, rows 110
  and 113, D-077). `abs(x - centre) < bound` is a subject, a centre and a
  bound in Python and JS alike, so a rewritten centre is an expected value
  changed and a widened bound a tolerance loosened.
- **JS assertions checkwash does not read** (#196 190.5, row 114, D-078). A
  throw, property, membership or type check is recorded with no strength, so
  deleting one is reported.
- **CI** (#196 191.x, row 112, D-079 to D-082). A runner site is a command
  that runs a test runner by a whole word. A trigger that never fires for a
  pull request is dead. A reworded runner and a removed pre-commit hook say
  what is known. A workflow or pre-commit config whose head side the reader
  cannot read, after a base side that ran tests, is high under a new
  escalator, `CI_BECAME_UNANALYSABLE`.
- **pytest selectors** (#196 184.x, row 105, D-083, D-084). A new selector
  in a root config is judged against the tests a targeted run collects too,
  and a path option counts only when it drops a base-suite test. A selector
  moved out of every run's command into the config is not new.
- **Skip guards, in the body and in the setup** (#196 183.2, rows 54 and 104,
  D-086, D-087). A skip whose guard the diff removed is reported, and a
  guarded skip in a same-file fixture or xunit setup carries its guard, judged
  as a guarded body skip is.
- **D6 per marker, and a conftest hook judged by its guard** (#208, #209,
  rows 72, 115 and 116, D-088, D-089). A compatibility gate holds only the
  marker it qualifies, and lends nothing to another disable on the unit. A
  collection hook whose effects run only under a guard that can be false is
  held as a guarded `collect_ignore` is; a hook that only reorders or labels
  its items is no control, and a conftest `pytestmark`, which pytest never
  reads, is reported at info.
- **Every `pytestmark` spelling** (#260, row 117, D-090). A `pytestmark` in a
  class body, under an `if`, `try` or `with`, written with `+=`, `.append`,
  an annotation, unpacking or a bound name, is read, with its path condition
  as its guard.
- **A guard removed from an existing suite-level control** (#261, row 116,
  D-091). Taking the guard off a `collect_ignore`, a collection hook or an
  `add_marker` skip in one is reported, as an edit that makes it always true
  already was.
- **A suite control's escalator** (#205, D-066). A blocking unguarded suite
  control says `COLLECTION_CONTROL_UNEXPLAINED` when the diff changes
  production and `NO_PROD_CHANGE_IN_DIFF` only when it does not; only the
  reason moves.

## Upgrading

The finding JSON shape, the rule IDs, the severity contract and the exit codes
are unchanged. The findings gain one escalator, `CI_BECAME_UNANALYSABLE`
(D-082), and one `shape` value, `inert_mark` (D-089). `--emit-ir` gains
optional fields: `test_obligations` on every file, and `predicate` and
`operand_source` on every assertion. IR_VERSION stays 2 (D-067). JS
`positive` now means what `ir/model.py` documents: `toBeDefined()`,
`toBeFalsy()`, `.exist`, `assert.exists` and `assert.isDefined` assert
negatively (D-069).

Some existing findings now carry a different fingerprint, which is why this is
a minor release ([D-092](../../DECISIONS.md)). An allowlist entry recorded on
v0.5.0 for one of these shapes stops matching and has to be recorded again:

- `TOLERANCE_LOOSENED` whose old side is a chai delta written as an integer
  or with an exponent, which is now spelled as an exact decimal (`abs=1.0` ->
  `abs=1`, `abs=5e-07` -> `abs=5E-7`; D-070);
- the file-level JS focus finding, now keyed by the path, `<file>` and
  `test.focused` (D-071);
- `SCOPE_DRIFT` on a JS/TS file whose test role came from its path alone and
  that declares no test, which now carries its table role (D-073), and on
  files beneath a test-support directory, which now carry the test role, with
  `SNAPSHOT_CODE_COCHANGE` whose production list held one (D-074);
- a widened Python hand-rolled bound, which moves from
  `EXPECTED_VALUE_CHANGED` to `TOLERANCE_LOOSENED`, and a JS hand-rolled
  check spelled through `expect(...)`, which six rules now key by its full
  text (D-077);
- `CI_WORKFLOW_TOUCHED` whose reason names a reworded runner or a removed
  pre-commit hook (D-081);
- in a repository whose CI passes explicit pytest targets, an existing config
  that gains a selector, now reported by the inventory's line (D-083);
- a guard removed from a unit's setup, reported by v0.5.0 as a skip added to
  the setup and now with the guard family's `guard:setup.<provider>.<effect>`
  identity (D-087);
- a mark bound to a name and applied by it, which v0.5.0 reported as
  `module.skip` or `module.xfail` on every test of the module, and which is
  now reported under the mark's own name on the tests it marks (D-090).

Some verdicts change too. Newly blocking, mostly on test-only diffs: the
changes listed above. Newly passing:

- a selector moved out of every run's command into the config (D-084's two
  cases);
- a collection hook whose effects run only under a guard that can be false,
  such as pytest's own `--runslow` recipe, and a module `pytestmark` whose
  `skipif` D6 qualifies, both at warn (D-088, D-089);
- a hook that only reorders or labels its items, a `pytest_ignore_collect`
  that never returns true, and a mark bound to a name and never applied, with
  no finding (D-089, D-090);
- a conftest `pytestmark`, now an info finding (D-089).

## Evidence and limits

- **Pull-request CI.** The merged heads of PRs #194–#265 were red only where
  `main` was red: `qualify` on its disclosed legacy v0.3.3 byte comparison
  (#201), and the tag-parity test on the nine OS/Python test legs, once the
  source had moved past the v0.5.0 tag. Dogfood, the verdict gate from its
  introduction on, and the source/wheel/pyz candidate contracts passed.
- **Sweeps.** Every round measured its cost against the engine before it on
  the fixed 1,800-commit Python sweep (the last 300 non-merge commits of
  attrs, click, flask, httpx, rich and starlette), and the later rounds also
  on commits selected from full project histories; each DECISIONS entry
  records its own. Against v0.5.0 itself, the release engine blocks the same
  48 of the 1,800 commits, moves no verdict and errors on none; one passing
  rich commit gains five warn findings, a Python 3.14 `skipif` bound to a
  name and applied by it (D-090). These are already used regression windows,
  not held-out measurements.
- **No JS/TS history replay.** Most of the JS/TS changes above were not
  measured on an independently selected JS/TS history ([#212](https://github.com/taipei49314/checkwash/issues/212)),
  so their false-positive cost is unmeasured.
- **Known open reports.** Among them: a test that starts requesting an
  existing always-skip conftest fixture still passes ([#223](https://github.com/taipei49314/checkwash/issues/223),
  row 104; its round is paused for this release), a skip guard on a class
  attribute is not evaluated ([#254](https://github.com/taipei49314/checkwash/issues/254)),
  a string `skipif` condition is read as always true ([#263](https://github.com/taipei49314/checkwash/issues/263)),
  and a duplicate survivor that a conftest fixture skips earns D10's credit
  ([#266](https://github.com/taipei49314/checkwash/issues/266), row 58). The
  rows above list each closure's residuals.
- **Recommended Action.** Under the one-release trust lag the recommended
  Action advances to **v0.5.0**, commit `24b60a2019a5900291ecb35ab8290f34af2d5438`.
  It has the fixes for the #172–#181 reports but none of the changes above.
  Its engine is measured separately against the current assertion contract;
  any failing case stays visibly failed.
- **Frozen comparisons.** The legacy v0.3.3 quality byte comparison keeps its
  disclosed cross-version mismatch.

The release record links the final-source checks on the tag: the full suite on
nine OS/Python legs, self-check, install-from-tag, corpus byte comparison and the
source/wheel/pyz assertion contracts. Human product acceptance remains separate
from mechanical qualification.

## Try it on a change you understand

With Python 3.11+ and Git, after publication:

```sh
pipx install checkwash==0.6.0
checkwash --version
checkwash demo
checkwash check HEAD~1..HEAD --format json --coverage-report coverage.json
```

Exit 0 means no blocking finding, exit 1 means a blocked change, and exit 2 means
an analysis/input error. GitHub provides the offline `checkwash.pyz`; the wheel
and sdist are also published through the existing PyPI workflow.

Checkwash remains alpha. A pass does not prove correctness or honesty. This
one-time publication authorizes no downstream re-pin and no other release.

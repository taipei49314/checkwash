# checkwash v0.3.0: content-bound exemptions, row identity, first use

**Alpha. The [1.0 criteria](../stability.md#what-must-change-before-10) are not met.**

This release changes detector logic. Five file-wide exemption rules move to
content-bound identities and their path-only keys are retired; parametrize
rows are compared by identity instead of by count; table-driven oracles that
delegate to a same-file helper or a literal-table fixture are read per row;
the findings and IR schemas advance to 2. The recommended Action pin advances
to the prior release, v0.2.13, under the one-release trust lag. The historical
benchmark records are unchanged and no fresh six-repository sweep for v0.3.0
is checked in.

## What changed since v0.2.13

- **Reviewed exemptions bind to content.** `GUARDRAIL_TOUCHED`,
  `CI_WORKFLOW_TOUCHED`, `TEST_FILE_UNPARSEABLE`, `SCOPE_DRIFT` and
  `SNAPSHOT_CODE_COCHANGE` used a fingerprint derived from the rule and path
  alone, so one recorded approval could cover a later change to the same
  path. Their keys now end in `/v2:` plus a SHA-256 over both analyzed
  snapshots and the rule-specific context; legacy keys stay visible but cannot
  suppress a finding. There is no automatic upgrade. See the
  [upgrade notes](../remediation-upgrade.md).
- **Parametrize rows have an identity.** `TEST_DISABLED` counts disabled or
  deleted rows by their cell text, so appending a new row no longer hides a
  disabled one; `EXPECTATION_DEFINITION_CHANGED` keys expectations by their
  input columns and reads every cell of a `pytest.param(...)` row
  ([#134](https://github.com/taipei49314/checkwash/pull/134),
  [#135](https://github.com/taipei49314/checkwash/pull/135)).
- **Table-driven oracles that delegate are read per row.** A same-file helper
  that is one bare `assert` with no message, and a zero-argument literal-table
  fixture, are inlined per row before the oracle is judged; anything else
  falls back to the general frontend
  ([#136](https://github.com/taipei49314/checkwash/pull/136)).
- **Conftest stand-ins and stored expectations** are resolved from strict
  snapshots, including imported `unittest.mock` forms
  ([#127](https://github.com/taipei49314/checkwash/issues/127),
  [#128](https://github.com/taipei49314/checkwash/issues/128),
  [#129](https://github.com/taipei49314/checkwash/issues/129)).
- **Installation and output fixes:** local hook installation and `doctor`
  agree on the runtime they bind; human diagnostics survive legacy Windows
  pipes; SARIF locations point at the analyzed source; workflow diagnostics
  explain rejected configurations; numeric-restoration and root-helper
  precision are bounded more narrowly.
- **Cross-interpreter determinism.** The release CI's byte-compare gate (every
  OS and Python version must emit byte-identical corpus findings, SPEC §8)
  ran for the first time since v0.2.13 and failed on Python 3.13: `ast.dump`
  omits empty fields by default there, and two places digested that text.
  Both now go through `stable_dump`, which pins the pre-3.13 format, so keys
  computed on 3.11 and 3.12 are unchanged and 3.13 agrees with them. The gate
  is green on the released commit for all nine OS/Python combinations.

The full commit list is in the
[GitHub Release](https://github.com/taipei49314/checkwash/releases/tag/v0.3.0)
and the dated section of [`STATE.md`](../../STATE.md).

## Try it on a change you understand

Use Python 3.11+ and Git. In a disposable virtual environment:

```bash
python -m pip install checkwash==0.3.0
checkwash --version
checkwash check HEAD~1..HEAD
checkwash check HEAD~1..HEAD --format json
checkwash check HEAD~1..HEAD --format sarif
```

Or with the single file:

```bash
curl -LO https://github.com/taipei49314/checkwash/releases/download/v0.3.0/checkwash.pyz
python checkwash.pyz --version
python checkwash.pyz demo
```

Run these inside your repository with two available commits. For a PR, use
`checkwash check BASE...HEAD` to compare the merge base with HEAD. Keep
normal tests and human review: a pass means no configured blocking finding
was found, not that the change is correct or honest.

Exit codes are **0 pass / 1 block / 2 engine error**. Capture the exit code
and stderr as well as stdout. The
[machine-interface contract](../stability.md#machine-findings-contract-findings_version--ir_version)
describes the schema-2 keys and the compatibility exception.

To stop a merge, install the [canonical workflow](../../README.md#required-check--the-only-configuration-that-blocks-a-merge)
and make its `checkwash` status context required. `checkwash doctor` inspects
local configuration; it cannot confirm live branch protection. See
[enterprise setup](../enterprise.md) for exemptions and configuration protection.

## If you recorded exemptions on v0.2.13

Exemptions for the five rules above are ignored by v0.3.0 and reported on
stderr as retired keys; `checkwash allow` rejects new legacy keys and
`doctor` counts retired and invalid entries separately. Re-review each change
and record a new content-bound key; the old reason does not contain the
content pair needed to reconstruct the approval. The
[upgrade notes](../remediation-upgrade.md) list the exact steps and the
runtime limits.

## Evidence and remaining work

The authoritative numbers in [`STATE.md`](../../STATE.md) are unchanged by
this release: the six-repository sweep records engine **0.1.46** and its
adjudication is dated 2026-08-26 (42/1800 blocked, 27/1800 adjudicated false
positive, 15/1800 legitimate policy block, 24/1800 recorded opaque production
changes, 12/12 classic decoys blocked). They are historical, in-sample
results. **This release changed detector behaviour and no fresh v0.3.0 sweep
record is checked in**; the [release process](../RELEASING.md#after-the-release)
says the corpus sweep is not optional in that case. Until it lands, treat the
historical rates as describing an older engine.

The current-state issues filed against v0.2.13 remain open and describe the
population this release aims at:
[#132](https://github.com/taipei49314/checkwash/issues/132) (LLM-arm
re-judge: 85 of 88 recorded escape families still passed, 90 of 90 recorded
honest refactors still blocked, on v0.2.13) and
[#130](https://github.com/taipei49314/checkwash/issues/130) (60 of those 90
are consolidations of N named tests into one parametrize, fixture or loop,
read as `TEST_DISABLED`/high). The parametrize-row and table-oracle changes in
this release are the first cut at that family; a re-judge on v0.3.0 is not in
this repository yet.

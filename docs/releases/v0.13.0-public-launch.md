## First-week working-tree, helper and virtual-environment fixes (D-205, D-206, D-207, D-208, D-212)

Four rough edges hit in ordinary repositories during first-week use are
removed:

- **The zipapp in the repository root and local hook settings
  ([D-205](../../DECISIONS.md), #602).** A check without a range and the Stop
  hook leave out the untracked zipapp checkwash itself runs from, with one
  stderr note, when neither `HEAD` nor the session base holds a file at that
  path. And `checkwash hook install --agent claude-code` (default `--local`)
  adds `.claude/settings.local.json` to the repository's Git `info/exclude`
  when Git neither tracks nor ignores it, while leaving an already-tracked file
  alone and naming how to untrack it.
- **Commonly named test helpers past the importer search limit
  ([D-206](../../DECISIONS.md), [D-212](../../DECISIONS.md), #603, #619).**
  Editing a test helper whose module name 64 or more unchanged Python files
  mention (such as `tests/base.py` or `tests/utils.py`) no longer stops every
  check with exit 2 under the default policy, unless the change renames the
  helper to that name. Each changed helper's module name is searched on its
  own, excluding paths in the diff; when a helper exceeds its own bounds (64
  unchanged hits or 48 unchanged test importers) or the run's 192 importer
  reads or 16 helper names, checkwash sets its unchanged importers aside,
  checks the helper module's own top-level non-`test*` (and non-`pytest_*` in
  `conftest`) functions directly across `REPAIR_REFUSED_PYTHON`
  (`ASSERT_WEAKENED`, `ASSERT_REMOVED`, `TEST_DISABLED`, `TOLERANCE_LOOSENED`,
  stand-ins and subject/derived rewrites), and emits an `analysis incomplete`
  note on stderr, the terminal report, SARIF `toolExecutionNotifications`, and
  non-blocking hook `systemMessage` output (`--format json` stdout is
  unchanged; under `[gate] on_engine_error = "block"`, non-`hook-json` `check`
  exits 2 with empty stdout when `importer_gaps` is non-empty).
- **Signed PowerShell activation scripts on Windows
  ([D-207](../../DECISIONS.md), #604).** The Authenticode `# SIG # Begin
  signature block` at the end of a PowerShell script is left out of the runner
  search when every line between its markers is `#`, a space and base64, so
  `python -m venv`'s signed `Activate.ps1` (whose base64 signature in Python
  3.11.9 spelled `tox` and `nox`) no longer blocks as an unparsed test runner.
- **Virtual-environment symlinks on Linux and macOS
  ([D-208](../../DECISIONS.md), #605).** In a check without a range, the Stop
  hook and the PreToolUse hook, untracked interpreter links under `bin/` or
  `Scripts/` and `lib64 -> lib` inside a non-root virtual environment holding a
  regular `pyvenv.cfg` (that neither `HEAD` nor the session base holds) are set
  aside instead of stopping the run with exit 2, unless a detector must read
  the path or pytest's collection can reach the environment. A range that adds
  or changes a committed link still exits 2 by design.

## Real test names on projected Python findings, test-shaped file notes, and strict inert EOF appends to `CLAUDE.md` (D-210, #610/#616, D-211/D-213)

- **Projected Python findings name the real test
  ([D-210](../../DECISIONS.md), #608).** Findings emitted from projected Python
  concrete, exception or local-auxiliary units (`test_concrete_*`,
  `test_exception_*`, `test_local_auxiliary_*`) now report the enclosing Python
  test's qualified name in `unit`, `message` and `fingerprint` across `term`,
  `json`, `sarif` and `hook-json`, while `--emit-ir` keeps the concrete
  `qualname` for alignment and adds optional `source_unit` on `Unit`
  (`FINDINGS_VERSION = 2`, `IR_VERSION = 3`). A non-transitioning edit to a
  Python test with one local subject capture (`total = invoice_total(...);
  assert total == 105.0`) no longer projects, keeping its source assertion text
  whether production code changed beside it or not. Exemptions recorded against
  `test_concrete_*`, `test_exception_*` or `test_local_auxiliary_*` keys move
  to the real test name and must be re-recorded
  ([upgrade notes](../embedding.md#v0120-to-v0130)).
- **Changed test-shaped files outside the parse gates (#610, #616).** When a
  diff changes, adds, deletes or renames a Python or JS/TS file that looks like
  a test module (inherited/mixin `test_*` methods in `tests/base.py`,
  non-default Python test names such as `tests.py` or `*_tests.py`, or JS/TS
  tests outside the zero-configuration paths such as `tests/*.js`, `*.cy.js` or
  `e2e/*.ts`) and neither test parser read it, `checkwash check` prints one
  `analysis incomplete: <N> test-shaped file(s) not analysed: ...` line on
  stderr, notes it in `term` and SARIF `toolExecutionNotifications`, and leaves
  verdicts, exit codes and `--format json` stdout unchanged.
- **Strict inert end-of-file appends to repository-root `CLAUDE.md` stay at
  `warn` ([D-211](../../DECISIONS.md), [D-213](../../DECISIONS.md), #611,
  #621).** Modifying a tracked root `CLAUDE.md` in place keeps
  `GUARDRAIL_TOUCHED` at `warn` (`GUARDRAIL_ADDITIVE`) when both sides are
  clean UTF-8 without newly added `Cf` or `Default_Ignorable` code points,
  `after` starts with the unmodified `before` line sequence, at least one blank
  line separates `before`'s last non-blank line from the added block, both
  sides end cleanly, frontmatter and Claude Code's non-anchored `---` slice
  match verbatim, and no added line contains `---`, `3+` consecutive
  `` ` ``/`~`, `<!--`/`-->` or `[label]:`. Prepends, mid-file insertions,
  adjacent appends without a blank line, fences, HTML comments, `---`
  delimiters, `[label]:` definitions, edits/deletions/reorderings, renames,
  deletions, and any edit to `AGENTS.md`, `.cursorrules`, `.claude/**`,
  `.checkwash/**` or `.greenwash/**` escalate to `critical` (`META`). Because
  checkwash does not interpret natural-language prose or follow `@path`
  imports, an appended plain-text paragraph or `@path` reference at clean EOF
  of `CLAUDE.md` stays at `warn` unless `--fail-on warn` is set
  ([known issues](../KNOWN-ISSUES-v0.13.0.md)).

## Bounded CPython 3.12+ `tokenize` memory, CLI snapshot reuse, and release verification (D-203, D-204, D-209, #607, #609, #613, #614, #617, #618)

- **CPython 3.12+ single-line `tokenize` memory bound, quiet `SyntaxWarning`
  parsing, and fail-closed shadow AST bounds (#613, #617, #618).**
  `syntax._chains` drops retained `TokenInfo.line` copies and pre-scans or
  condenses complete non-chain physical lines past `2,048` characters (while
  preserving multiline PEP 701 `fr"..."`/`rf"..."` f-strings), preventing
  CPython `3.12.3`'s `O(K * L)` `TokenInfo.line` memory blowup (fixed upstream
  in `3.12.14`); `syntax.py`, `frontend.py`, `engine.py` and `shadow_models.py`
  suppress `SyntaxWarning`/`DeprecationWarning` on analysed Python source; and
  `shadow_imports.py`, `shadow_controls.py` and `shadow_providers.py` convert
  deep-AST `RecursionError`/`MemoryError` and `parse_ok=False` outcomes into
  `EngineError`.
- **Shared `GitSnapshot` reads and Phase 2 decomposition (#607, #609).** The
  CLI shares one resolved `GitSnapshot` across base policy, task contract,
  manifest batch reads, range listing and paired pytest configs, and five large
  engine/frontend/gating modules were split into smaller helpers with zero
  verdict change.
- **Hosted macOS/Linux release verification, compact PR receipts, and 1.0
  groundwork ([D-203](../../DECISIONS.md), [D-204](../../DECISIONS.md),
  [D-209](../../DECISIONS.md), #596, #600, #606, #614, #616).** From v0.13.0
  each release runs one hosted verification on GitHub-hosted `macos-latest`
  (Apple silicon) and `ubuntu-latest` across Python 3.11–3.13, at the release
  merge `M` before the tag and on the published wheel, sdist, pyz and Action
  before PyPI approval (D-204); collector tests resolve symlinked temporary
  paths for macOS `/var` (#600, #614); ordinary pull requests use compact
  single-line PJU digest receipts with GitHub Actions App `15368` ruleset
  binding while release stages keep full `3x283` qualification (D-209); and
  `release.yml` pins `pypa/gh-action-pypi-publish` v1.14.3 (#596).

## Evidence and scope

Each release stage (pull request, main, tag, release event and public visitor)
is collected afresh on LAPTOP-01AGNPJU, Windows 11, CPython 3.11.9,
`HUMAN_AUTHORIZED_LOCAL_PJU_NOT_EC_POOL`, one route for the whole receipt
chain, as for v0.11.0 and v0.12.0. Native Linux, macOS and other Python
versions are `NOT_RUN` for the release-stage receipts themselves. Alongside
them:

- Before merging the release pull request, the release head `R` runs the full
  23,358-test suite (`23,425` JUnit items including 67 subtests) with zero
  deselects across six isolated runtimes on LAPTOP-01AGNPJU (`HUMAN_AUTHORIZED_LOCAL_PJU_NOT_EC_POOL`):
  Windows 11 x86_64 CPython `3.11.16`, `3.12.14` and `3.13.15`, and WSL2
  Ubuntu 24.04.4 LTS x86_64 CPython `3.11.18`, `3.12.16` and `3.13.18`
  (including both Linux perf-gate budgets), with byte-identical
  `tools/emit_corpus.py` output across all six legs; macOS is `NOT_RUN` locally.
- At the release merge `M` (before the tag) and on the published wheel, sdist,
  pyz and Action (before PyPI approval), 0.13.0 also runs the hosted release
  verification ([RELEASING](../RELEASING.md#hosted-release-verification),
  D-204) on GitHub-hosted `macos-latest` (Apple silicon) and `ubuntu-latest`
  with Python 3.11, 3.12 and 3.13 (`HUMAN_AUTHORIZED_GITHUB_HOSTED_NOT_PJU_RECEIPT`),
  recorded in the publication record. Source, wheel and pyz agreement and
  hosted verification are not the one-run nine-leg cross-platform comparison,
  which stays unexecuted.

The public installation manifest and the README pins advance only after the
public files are verified. **1.0 readiness remains NOT_MET**: these in-sample
comparisons establish no held-out rate, completed adoption cohort or macOS
perf-budget verification, and Nelson's stop before 1.0 remains in force.

# CheckWash 0.13.1

This patch covers a Python test that keeps its assertion while quietly changing which function it calls. In the case reported in #635, the test originally called the project's billing function. A new function with the same name appeared below the import in the test file. The assertion then passed using that local function, while the billing calculation still had the same defect. CheckWash 0.13.0 passed this change. The released CLI reports `TEST_PATCHES_SUBJECT` at `high` and blocks it at the default threshold. [Original report](https://github.com/taipei49314/checkwash/issues/635) · [Merged fix](https://github.com/taipei49314/checkwash/pull/640)

The check uses the existing test's direct equality assertion. Its text stays the same on both sides of the change. CheckWash can trace the import to a function declared in an unchanged project module and see that a new, plain module-level function now supplies a literal result or computes it from its arguments. The finding identifies the affected test and points to the local definition.

The patch also covers a change to a numeric pytest fixture. When the fixture defines a local replacement for the imported function and returns the result of calling it, the existing generator-to-parameterized-test check can report the replacement. Its reviewed regression covers `return square(2)` and preserves the finding for the equivalent assignment. [Fixture regression](https://github.com/taipei49314/checkwash/blob/0477013159face076a2c6a887f9d5b235c76d5e5/tests/test_generator_fixture_subjects.py) · [Coverage limits](../KNOWN-ISSUES-v0.13.1.md)

# v0.7.0: release evidence and limits

v0.7.0 includes bounded imported-helper skip guards, strict Git input failure
handling and supported synchronous JS/TS catch-swallowing detection, alongside
the Python, JS/TS and CI changes merged since v0.6.0. These are bounded syntax
and input proofs, not a general control-flow or runtime verifier.

Imported-helper guards retain their defining source and unknown fallback;
incomplete namespace isolation and compatibility-token fail-open remain limits.
Git input failures are errors rather than ordinary passes. A newly added catch
that suppresses a supported synchronous assertion uses BROAD_EXCEPT_ADDED;
direct rethrows and setup-only catches remain controls.
[Catch boundary](https://github.com/taipei49314/checkwash/blob/v0.7.0/docs/js-catch-swallowing.md)
· [Git input contract](https://github.com/taipei49314/checkwash/blob/v0.7.0/docs/git-input-failure-qualification.md)

## Use it and preserve the result

Use Python 3.11 or later and Git. After the release asset is available,
download [checkwash.pyz](https://github.com/taipei49314/checkwash/releases/download/v0.7.0/checkwash.pyz)
and try a change you understand:

    python checkwash.pyz --version
    python checkwash.pyz check BASE..HEAD --repo /path/to/repository --format json

Exit 0 passes the configured gate, exit 1 blocks, and exit 2 is an input or
analysis error. Retain stdout, stderr and exit status. The JSON finding interface
remains checkwash_findings_version: 2. A pass does not prove a change correct or
honest; warnings and skipped files still need review.

The recommended Action stays at the prior published v0.6.0 commit
8c70efbf93975bf3210acb8eafbaf4b38044a770. CLI upgrades do not change caller Action
pins, and the prior engine lacks later CLI fixes. A CI job must run
unconditionally and its status check must be required by branch rules to block
a merge; workflow inspection does not verify live branch protection.
[Action reference](https://github.com/taipei49314/checkwash/blob/v0.7.0/action/README.md)

## Limits that remain

The JS set is prospectively registered in-sample/nonblind. Legacy input integrity
remains UNKNOWN, with zero confident legacy pairs. Output agreement is not a
semantic truth-label corpus or a held-out/general false-positive rate. Lexical
callback representation does not prove invocation; unsupported predicates,
typed headers, labels, classes, async completion and unsupported control flow
remain outside the bounded catch proof. Git worktree snapshots remain non-atomic
and do not detect every change-and-revert. Formal A–D held-out/custody work and
the protected historical materializer remain separate and incomplete.

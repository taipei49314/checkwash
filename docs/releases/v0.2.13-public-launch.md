## Try it on a change you understand

Use Python 3.11+ and Git. In a disposable virtual environment:

```bash
python -m pip install checkwash==0.2.13
checkwash --version
checkwash check HEAD~1..HEAD
checkwash check HEAD~1..HEAD --format json
checkwash check HEAD~1..HEAD --format sarif
```

Run these checks inside your repository with two available commits. For a PR,
use `checkwash check BASE...HEAD` to compare the merge base with HEAD.
Keep normal tests and human review: a pass means no configured blocking
finding was found, not that the change is correct or honest.

Exit codes are **0 pass / 1 block / 2 engine error**. Capture the exit code
and stderr as well as stdout. An invalid revision can return exit 2 with no
JSON on stdout even when JSON was requested. The
[machine-interface contract](../stability.md#machine-findings-contract-findings_version--ir_version)
describes the actual keys and pre-rename compatibility exception.

To stop a merge, install the [canonical workflow](../../README.md#required-check--the-only-configuration-that-blocks-a-merge)
and make its `checkwash` status context required. `checkwash doctor` inspects
local configuration; it cannot confirm live branch protection. See
[enterprise setup](../enterprise.md) for exemptions and configuration protection.

## Verify the download and publication

Download the wheel, sdist or `checkwash.pyz` from the versioned release above.
Compare its complete SHA256 with the release asset digest. PyPI's wheel and
sdist must match the same-named GitHub assets; the zipapp is a GitHub asset.
Run `checkwash --version` or `python checkwash.pyz --version` on the surface
you installed. A file's existence alone does not establish a successful run.

The versioned Release page records the publishing workflow and available
assets. The [release process](../RELEASING.md#check-the-public-package-page)
requires metadata, rendered links and downloaded-byte checks before reporting
publication complete. Local candidate builds are not published assets.

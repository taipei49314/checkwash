# CheckWash 0.13.2 candidate

Follow the [verified installation guide](../install.md) for the recommended CLI, standalone download and GitHub Action pin. The guide currently recommends 0.13.1 and advances once the new public packages and Action have been checked.

## What changes for users

- Python tests can import an existing first-party module, including projects where the distribution and import names differ. Moving an unchanged test can keep its move credit when unused imports are removed. CheckWash resolves providers at both file locations so a switch to a different same-named module remains visible. [First-party imports](https://github.com/taipei49314/checkwash/pull/643) · [Move credit](https://github.com/taipei49314/checkwash/pull/644) · [Moved providers](https://github.com/taipei49314/checkwash/pull/651) · [Sibling imports](https://github.com/taipei49314/checkwash/pull/650)
- CLI errors identify the Git input to fix. Reports distinguish reviewed exemptions from active findings, explain Ruff rule changes per file, and give a concrete repair when a test calls its own replacement function. [Git inputs](https://github.com/taipei49314/checkwash/pull/647) · [Exemptions](https://github.com/taipei49314/checkwash/pull/645) · [Ruff](https://github.com/taipei49314/checkwash/pull/648) · [Reports](https://github.com/taipei49314/checkwash/pull/649)
- The package description and the project README point to the same verified installation guide. [First-use guide](https://github.com/taipei49314/checkwash/pull/652) · [PyPI description](https://github.com/taipei49314/checkwash/pull/656)

## Measured scan time and verdicts

On a 7,104-file Django checkout, the median time for the #22143 range fell from 16.09 to 7.14 seconds. For #22285 it fell from 15.70 to 6.86 seconds. The before and after commits were `059fb4e3` and `f0d202f3`, both after the earlier parse-cache repair. Each timing is the median of four fresh Windows CPython 3.12.14 processes per engine and range on LAPTOP-01AGNPJU. The JSON, stderr and exit codes matched within each range. [Parse-cache change](https://github.com/taipei49314/checkwash/pull/646) · [Django measurements](https://github.com/taipei49314/checkwash/pull/655)

The published 0.13.1 zipapp (tag commit `62656df8`, release merge `5e2a89ef`) and the candidate engine `f0d202f3` produced byte-identical stdout and stderr and identical exits on all 3,600 fixed in-sample commits. Both passed 1,726 and blocked 74 Python commits. Both passed 1,748 and blocked 50 JS/TS commits and returned the same two snapshot errors. The release base has the same engine tree.

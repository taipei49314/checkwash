# Checkwash v0.3.4: bounded family repairs, with retained limits

Checkwash v0.3.4 repairs known ways that row changes, helper refactors and
substituted runtime providers could lose useful test evidence or produce
false positives. It statically reads a Git diff, has no runtime dependencies
or LLM calls, makes no network calls during analysis and never executes the
reviewed code. It remains alpha: passing does not prove correctness or honesty.

## Try it on a change you understand

Python 3.11+ and Git are required. On Windows PowerShell:

```powershell
curl.exe -LO https://github.com/taipei49314/checkwash/releases/download/v0.3.4/checkwash.pyz
python checkwash.pyz --version
python checkwash.pyz demo
```

On macOS/Linux or Git Bash, use `curl -LO` with the same URL. The offline
demo replays eight tampering cases and one honest fix. In a Git repository:

```bash
python checkwash.pyz check HEAD~1..HEAD
python checkwash.pyz check BASE...HEAD --format json
# Fixed package installation:
pipx install checkwash==0.3.4
```

The first command needs at least two commits. Three dots compare from the
merge base. Exit 0 means no blocking finding under the configuration, exit 1
means a block to review, and exit 2 is an input or analysis error. The default
threshold is high, so a warning may still pass. Keep running normal tests.

## What changed

- Row disabling and vanished-row answer replacement retain concrete input
  identity and multiplicity. Surviving-input answer changes keep their
  original rule owner; unrelated rows cannot supply replacement witnesses.
- Bounded table, helper, class and wrapper proofs preserve concrete oracles
  through supported refactors. Literal constant renames and helper/loop
  expectation provenance preserve value origins and native assertion ownership.
- Runtime-shadow and stand-in installation checks use first-party sources,
  import identity, activation timing and complete inventory where needed.
- Pytest collection changes compare supported literal option values. Unknown
  startup context, dynamic behavior and unsupported forms retain conservative
  handling. A new stress job alone does not prove the old matrix equivalent.

The implementation and exact bounds are in [PR #155](https://github.com/taipei49314/checkwash/pull/155),
[family remediation](https://github.com/taipei49314/checkwash/blob/v0.3.4/docs/family-remediation-2026-09-12.md),
[input roles](https://github.com/taipei49314/checkwash/blob/v0.3.4/docs/param-input-roles.md)
and [subject integrity](https://github.com/taipei49314/checkwash/blob/v0.3.4/docs/subject-integrity.md).
Syntactic input consumption does not prove arbitrary callee dependence; the
documented no-op-callee residual remains. Equivalent provider copies alone
do not earn unrelated repair credit.

## Upgrade boundaries

The CLI/package is **v0.3.4**. Under the one-release trust lag, the recommended
GitHub Action is **v0.3.3**, peeled commit
`498064f095bd892550a917219798b3f44c42ccef`. That Action includes the earlier
shared immutable-fixture precision fix, but **does not contain these new
family repairs or the quality preview**. A CLI upgrade does not update a
deployed Action. Make the deployed version's unconditional `checkwash`
status required if it should block merges.

IR and findings schema versions remain 2. Six optional IR evidence fields
have empty defaults; they change the emitted IR bytes. Existing rule IDs,
severity/strength values, alignment parameters, exit codes and fingerprint
contracts remain. The earlier v0.3.0 exemption migration still applies when
upgrading from v0.2.13; follow its
[migration notes](https://github.com/taipei49314/checkwash/blob/v0.3.4/docs/remediation-upgrade.md).

The package also includes the limited coverage/Ruff/mypy quality preview
already present in the reviewed source. Publication is not completion of its
natural-case acceptance or completeness evaluation. Its frozen T-255 legacy
byte comparison remains red. See the
[quality guide](https://github.com/taipei49314/checkwash/blob/v0.3.4/docs/quality-adoption.md).
Report-mode smoke success does not verify effective CI enforcement or live
branch protection. No historical expectation or frozen comparator was changed.

## Release verification and continuing limits

The release process requires unchanged full tests, actual tag/source identity,
the nine-platform raw-byte comparison and package checks on the release
source. The GitHub release build additionally runs full-engine pyz process
qualification and a fresh wheel install. Published wheel/sdist hashes must
match between GitHub and PyPI; the pyz's source members and version are
verified separately. Cross-build ZIP byte reproducibility is not promised.
Final release-source and public-asset receipts belong with the
[v0.3.4 release](https://github.com/taipei49314/checkwash/releases/tag/v0.3.4),
not retroactively in the historical rows above.

This one-time publication is authorized under estate T-332 and refreezes
after verification. It does not waive the frozen T-255 result, remove known
escapes or declare 1.0 readiness. Future releases and unrelated downstream
pin advances require their own authorization. See
[stability and adoption cost](https://github.com/taipei49314/checkwash/blob/v0.3.4/docs/stability.md)
and [known gaps](https://github.com/taipei49314/checkwash/blob/v0.3.4/docs/adversarial-catalog-2026-09.md).

# Checkwash v0.3.3: shared-fixture precision, with measured limits

Checkwash reads a Git diff and flags known ways of weakening verification:
deleted assertions, skipped tests, relaxed expectations and CI checks that
stop failing. It runs locally, has no runtime dependencies or LLM calls,
makes no network calls during analysis and never executes the reviewed code.
It remains alpha. A pass is not proof of correctness or honesty.

## Try it on a change you understand

Python 3.11+ and Git are required. On Windows PowerShell:

```powershell
curl.exe -LO https://github.com/taipei49314/checkwash/releases/download/v0.3.3/checkwash.pyz
python checkwash.pyz --version
python checkwash.pyz demo
```

On macOS/Linux or Git Bash, use `curl -LO` with the same URL. The demo
replays eight tampering cases and one honest fix without downloading a repo.
In a repository with at least two commits:

```bash
python checkwash.pyz check HEAD~1..HEAD
python checkwash.pyz check BASE...HEAD --format json
```

`HEAD~1..HEAD` checks the last commit; `BASE...HEAD` uses the merge base.
Exit 0 means no blocking finding under the configuration, exit 1 means a
block to review, and exit 2 is an input or analysis error. The default
threshold is high, so a visible warning may still pass. Keep running tests.

For a fixed CLI install: `pipx install checkwash==0.3.3`. The recommended
GitHub Action remains one release behind, at v0.3.2, commit
`4ad6e31019dd40e69f46f3f0ac24d37bbdad31ac`. It carries the v0.3.0 engine and
does **not** include this release's shared-fixture precision change. A CLI
upgrade does not update an existing Action. To enforce a deployed workflow,
make its unconditional `checkwash` status required in branch rules.

## What changed

Several tests may consume the same `pytest.fixture(params=...)` without
losing the existing concrete-oracle proof when each parameter is a literal
scalar or recursively immutable tuple. Multiple consumers of mutable
list/dict/set values remain excluded because pytest can reuse those objects.
The complete-module, ordered original-oracle prefix, startup-context and
case-expansion checks remain. No schema, fingerprint, severity or alignment
contract changes are included.

The before/after tests for historical cases 012 (`percent`) and 032
(`common_suffix`) retain the original examples and add checks. Both versions
pass good production and fail buggy production through completed test
failures, without fixture errors or skips. The candidate changes these two
cases from block to pass. [Implementation and qualification](https://github.com/taipei49314/checkwash/pull/150)

## Limits and release boundary

Python is the primary frontend; JS/TS support is a bounded text scan. Dynamic
execution, broad fixture semantics, other known escape families and the
three invalid refactor fixtures are outside this patch. A blocked change
may be legitimate, and a passing change may still weaken tests.

The final release must pass the unchanged test suite, advertised-tag source
identity, visitor install, dogfood and nine-way cross-platform byte comparison.
PyPI's description must match the tag README; wheel/sdist hashes must match
the GitHub Release assets. The pyz is the published artifact, not a promise
that ZIP bytes are identical across separate builds. After those checks and
the downstream release-pin handoff, this release is frozen under estate
T-229. There is no automatic next release.
